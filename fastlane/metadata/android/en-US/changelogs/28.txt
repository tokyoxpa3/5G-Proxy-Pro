- Changed: the health check now asks exactly one question — did any HTTP response come back? — and nothing else. A carrier's out-of-data portal page, a 302 to a login screen, a 204 that carries a body, even a 5xx from the endpoint itself: all of them prove the data plane is carrying bytes, and rebuilding the proxy cannot fix any of them. The diagnostics line still shows the raw status code (`ok 80ms (200)`) without judging it
- Fixed: the response body is no longer read at all, only the status line. A portal page costs nothing, and a redirect is no longer followed just to be thrown away
- Fixed: the health check always probed its endpoints in a fixed order, so on a network where the first endpoint is blocked it paid a full timeout on every round — thousands of times a day while the proxy sat idle. The endpoint that succeeded last time is now tried first, so a healthy network costs one request
- Fixed: a completely failing egress probe could take over 20 seconds (two STUN plus two echo timeouts) while running every 15 seconds, which stretched its own cycle. It now runs on an 8-second budget, with timeouts clamped to whatever is left
- Fixed: when the cellular link could be bound and TCP connected but not a single payload byte came back, the watchdog classified it as a dead network and rebuilt the proxy every ~45 seconds, dropping every live connection while never fixing the data plane. This case is now its own state: at most two rebuilds, then it stops and tells you instead of tearing down your connections forever
- Fixed: the built-in self-test's data step required the response to start with `HTTP/`, so a carrier portal page or any non-standard reply made the whole test report a failure even though packets had travelled the entire proxy path. It now only asks whether any byte came back
