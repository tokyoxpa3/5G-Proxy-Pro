- Fixed: the throughput collapse after several IP changes. Tearing a connection down while megabytes were still queued toward the client left the socket as a kernel orphan retransmitting in the background, with the retransmission timeout backing off to 120 seconds. After three or four rotations this reached 126 half-closed sockets and 131 orphans, pushing kernel TCP memory to 201,903 pages — past the 178,847-page pressure threshold — at which point the kernel starts dropping packets and every new connection is pinned near 280 KB/s. Closing a socket with a non-empty send queue now resets it and discards the queue instead of retransmitting
- Fixed: sockets whose queue was already empty still close normally, so the last bytes of a response are never truncated
- Changed: the `HealthProbe:` line in diagnostics now lists every endpoint with its outcome (`gstatic.com=SocketTimeoutException; apple.com=ok 95ms (200)`) instead of a single `fail 5000ms: ...`
- Changed: the health check now tries the endpoint that answered last time first. With a fixed order, a network where the first endpoint is blocked paid a full timeout on every round — thousands of times a day while the proxy sat idle
- Fixed: the health check no longer reads the response body at all, only the status line. A portal page costs nothing, and a redirect is no longer followed just to be thrown away
- Fixed: a completely failing egress probe could run past 20 seconds (two STUN plus two echo timeouts) while the loop runs every 15 seconds, so it stretched its own cycle past a minute. It now has an 8-second total budget, with each attempt's timeout clamped to whatever is left
- Fixed: the built-in self-test's data step required the response to start with `HTTP/`, so a carrier portal page or any non-standard reply made the whole test report a failure even though packets had travelled the entire proxy path. It now only asks whether any byte came back
- Changed: the `Dns:` diagnostics line now distinguishes "a query was sent and failed" from "negative cache hit". Both used to print `failed`, so a reader would conclude DNS was failing every time when in fact no query had been sent
- New: the diagnostics report has a `DnsPath:` line showing whether the last lookup went through `DnsResolver`, `getAllByName`, or was rejected by backpressure. `DnsStats` is always zero on API 29+, which is easy to misread as "DNS never ran"
- Fixed: egress probing now backs off exponentially while it keeps failing (15s → 30s → 60s → … capped at 5 minutes). A dead path used to cost two HTTPS requests every 30 seconds — thousands of wasted requests a day. One success returns it to the normal cadence
